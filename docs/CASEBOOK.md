# Requirement routing

The agent reads the brief and evidence. The CLI should not guess visual intent from one adjective such as “Wonderous.” Record whether a claim came from observed source code, a screenshot, a video, or an inference.

## A. An existing illustrated scene should gain depth

Inspect whether genuine transparent planes exist. Prefer opaque background, coherent landmark masses, foreground, foliage, and actors. Register every piece to one source canvas and verify the settled composition before adding movement. A flattened image cannot acquire real separable geometry merely by duplicating it and clipping arbitrary rectangles.

Implemented path: image planes with explicit bounds, anchors, timing, pointer depth, and scroll scale. Missing artwork or alpha extraction is an asset-pipeline task, not an implicit CLI success.

## B. A building should assemble in parts

Use semantic structural masses: complete roofs, continuous tower faces, supports, and terrain. Do not slice through a rigid mass to manufacture animation count. Final assembly must match the intact registered silhouette. Entry ordering follows construction/readability, not a universal seven-part template.

Current status: structural polygon assembly is outside schema v1. Use a reviewed custom Flutter widget or implement a new runtime capability and corresponding tests. Do not silently flatten the requirement to a fade or advertise unimplemented polygon support.

## C. Water, plants, or characters should feel alive

First identify the physical support, pivot, depth, and permitted movement. Keep rigid architecture stable. Subtle whole-piece sway, a local water shader, a posed frame swap, and articulated animation are different capabilities. Do not describe a two-frame cutout as a character rig.

Current status: entry transforms and explicit depth inputs are supported. Ambient effects, water shaders, and articulated rigs require custom Flutter code and device review.

## D. The page should enter on scroll or gesture

Identify what controls time: navigation progress, vertical entry gesture, pointer location, or an ambient clock. Couple effects that belong to the same transition. Keep pointer motion separate. Handle repeated/reversed input and stale asset completions before visual polish.

Current status: the stage accepts progress, pointer, and scroll separately. The convenience player owns entry only. An application must wire real gestures, routes, back behavior, and scroll ownership. A video showing an artificial cursor is not evidence that those controls work.

## E. Content is dense, multilingual, or personal

Use real Flutter text with semantic structure, wrapping, large-text behavior, contrast, and responsive layout. Keep text and QRs out of generated artwork. Preserve exact names, claims, schedules, and identity matches. Do not invent missing names, endorsements, event facts, or translated identity details.

Current status: user-owned overlay and app widgets hold content. Typography intelligence, QR tools, and localization are not implemented in the CLI. Production source copy and portraits are not sample assets.

## F. One scene must work on mobile and a wide screen

Choose source registration and a deliberate focal crop. Review portrait, landscape, and wide viewports at intermediate frames, not only the endpoint. Verify text safe areas separately from image cropping. “Responsive” is not just scaling the entire desktop composition down.

Current status: contain/cover and focal position are supported. Per-breakpoint art direction, alternative crops, typography, and scene composition remain explicit user widgets or future contract extensions.

## G. The result is being generalized into an open-source tool

Separate the reusable method from source-project data. Code license, font license, source-art license, generated-output rights, likeness permissions, and trademark treatment are independent checks. Start with synthetic fixtures and assets cleared for redistribution. Preserve attribution for any actual upstream code adaptation.

Current status: this repository contains independent new code and original geometric fixtures. It carries no production artwork, named-event content, portraits, logos, QRs, or original reference illustrations.
